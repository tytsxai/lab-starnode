# StarNode 生产运维手册（MVP）

> 目标：以最小复杂度保障可上线、可回滚、可定位问题。

## 1. 运行前提

1. Node.js 固定 `22.x`（根目录 `.nvmrc`）。
2. 构建与发布必须通过 `npm run ci:verify`。
3. 禁止在生产开启 `STARNODE_ALLOW_UNSAFE_BUILD=1`（仅允许本地排障临时使用）。

## 2. 发布前检查（最小闭环）

```bash
nvm use
npm ci
npm run ci:verify
```

然后手工验证：
- 创建/编辑/删除/撤销
- 冰封/解冻/批量迁移
- 跨标签页同步（两个标签页同时打开）
- 健康检查：`GET /api/health` 返回 `200`

## 3. 生产健康探针

- 路径：`/api/health`
- 预期：
  - HTTP `200`
  - JSON 含 `status: "ok"`
  - 字段 `now` 为 ISO 时间

## 4. 可观测性（当前版本）

### 4.1 前端异常日志
- 路由级异常：`apps/web/app/error.tsx`
- 全局渲染异常：`apps/web/app/global-error.tsx`
- 存储不可用/落盘失败：`packages/storage/src/index.ts`
- 日志关键字：
  - `[StarNode][route-error]`
  - `[StarNode][global-error]`
  - `[StarNode][storage-unavailable]`
  - `[StarNode][storage-save-failed]`

### 4.2 最低接入建议
- 若部署在 Vercel：启用 Runtime Logs 并按关键字检索。
- 若部署在自建平台：采集浏览器 `console.error`（Sentry/LogRocket 等任选其一，先接一个）。

## 5. 数据备份与恢复（localStorage）

> StarNode 当前为本地优先，数据主存储在浏览器 `localStorage`。

### 5.1 手工备份（浏览器控制台）
```js
const key = 'starnode:notes'
const raw = localStorage.getItem(key)
console.log(raw)
```

将输出保存为本地文件（例如 `starnode-notes-backup.json`）。

### 5.2 手工恢复（浏览器控制台）
```js
const key = 'starnode:notes'
const backup = '在这里粘贴备份 JSON 字符串'
localStorage.setItem(key, backup)
location.reload()
```

## 6. 失败处理与回滚

1. 发布失败（构建/启动失败）：
   - 立即停止发布，继续使用上一稳定版本。
2. 发布后异常（错误率升高）：
   - 先回滚到上一版本，再定位根因。
3. 回滚目标：
   - 10 分钟内恢复服务可用性。

## 7. 常见故障速查

- **症状：构建通过但线上报错**
  - 检查是否误开 `STARNODE_ALLOW_UNSAFE_BUILD=1`。
- **症状：多标签页互相覆盖**
  - 预期行为是“持久化快照优先”；若出现频繁覆盖提示，提示用户避免长期并行编辑同一数据集。
- **症状：页面白屏**
  - 查看控制台是否出现 `[StarNode][global-error]`，记录 `message + stack + 复现路径`。
- **症状：数据未持久化（刷新后丢失）**
  - 检查控制台是否出现 `[StarNode][storage-unavailable]` 或 `[StarNode][storage-save-failed]`，优先排查浏览器隐私策略或 localStorage 配额。
